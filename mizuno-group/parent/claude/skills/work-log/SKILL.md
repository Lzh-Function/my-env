# work-log スキル

## 概要

実装、改良、バグ修正、テスト通過、リファクタリング完了など、作業の区切りごとに `agents-work-log` ディレクトリへ日次の作業ログを追記する。

ログは常に `agents-work-log/YYYY-MM-DD.md` に記録する。

## 使用タイミング

以下のいずれかに該当する場合、このスキルを使用する。

- ユーザーが「進捗をログに記録して」と依頼した
- 実装または修正が完了した
- テストが通過した
- バグの原因と解決策が明確になった
- リファクタリングや設計変更が一区切りついた
- 作業内容を後から追跡できる形で残す必要がある

## 実行手順

1. `agents-work-log` ディレクトリが存在するか確認する。
2. 存在しない場合は作成する。
3. 今日の日付に対応する `agents-work-log/YYYY-MM-DD.md` を確認する。
4. ファイルが存在しない場合は新規作成する。
5. ファイルが存在する場合は、既存内容を変更せず、末尾にのみ追記する。
6. 作業内容、遭遇した問題、解決策、テスト結果を簡潔に記録する。

## ログファイル形式

**ファイル名：**

```text
agents-work-log/YYYY-MM-DD.md
````

例：

```text
agents-work-log/2026-06-02.md
```

## 追記形式

```markdown
## [15:30] テスト通過

### 対象ディレクトリ
- src/components/FormInput.tsx
- tests/components/FormInput.test.ts

### 実装内容
- バリデーション処理を改善した。

### 遭遇したバグ
- 入力値のチェックが正しく動作しなかった。
  - 原因：正規表現の条件が不完全だった。
  - 解決：入力仕様に合わせて正規表現を修正した。

### テスト結果
- ユニットテスト：全パス
- 統合テスト：全パス

---
```

## 記録ルール

* 日付と時刻は実行環境のローカル時刻を使用する。
* 不明な項目は推測で補完せず、「記載なし」とする。
* 直前の作業内容から明らかに判断できる場合のみ、簡潔に要約して記録する。
* ログは後から読み返しやすいように、事実ベースで簡潔に書く。
* コード、エラーメッセージ、テストコマンドは必要に応じて記録する。

## 注意事項

* 既存の内容は絶対に編集・削除しない。
* 既存ログの整形、並べ替え、見出し変更も行わない。
* 常にファイル末尾への追記のみ行う。
* 既存ファイルがない場合のみ新規作成する。
