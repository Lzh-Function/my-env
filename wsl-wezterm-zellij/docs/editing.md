# 実践編: ファイル編集の実戦テクニック(研究ワーク向け)

[`lazyvim.md`](./lazyvim.md)で扱った基本(モード・移動・LSP)の一歩先、
「コピペ」「カーソルジャンプ」「複数ファイル編集」を実際の研究コード
(モデル定義・学習スクリプト・config・前処理パイプラインなど)に即して深掘りする。
データサイエンス/深層学習/創薬アプリケーション研究の作業を具体例に使う。

キーバインドはこの環境の実際の設定から検証済み(`mini.ai`のテキストオブジェクト、
`nvim-treesitter-textobjects`の移動キーなど、ソースを直接確認した上で記載している)。

## 最初にこれだけ覚える

| したいこと | キー |
|---|---|
| コピー(1行) | `yy` |
| カット(1行) | `dd` |
| 貼り付け | `p`(後ろ) / `P`(前) |
| 関数まるごとコピー | カーソルを関数内に置いて`yaf` |
| クラスまるごとコピー | カーソルをクラス内に置いて`yac` |
| 次の関数へジャンプ | `]f` / 前の関数へ `[f` |
| 特定の文字にジャンプ(同じ行) | `f<文字>` |
| 画面上の任意の場所へジャンプ | `s<2文字>`(Flash) |
| ブックマークして戻る | `ma`でマーク → 別の場所へ → `` `a ``で戻る |
| 直前のジャンプ地点に戻る | `Ctrl+o`(戻る)/ `Ctrl+i`(進む) |
| 複数ファイルを横断置換 | `<space>sr`(Search and Replace) |
| 数値を1増減 | `Ctrl+a` / `Ctrl+x` |
| 同じ編集を繰り返す | `.`(ドットリピート) |

## コピー・カット・ペースト(レジスタという考え方)

VSCodeの「クリップボードは1つ」という感覚と違い、Vimは**レジスタ(register)**という
名前付きの入れ物を複数同時に使える。

### 基本(無名レジスタ)

| したいこと | キー |
|---|---|
| 1行コピー | `yy` |
| 1行カット | `dd` |
| 選択範囲をコピー | ビジュアルモード(`v`)で選択 → `y` |
| 選択範囲をカット | ビジュアルモードで選択 → `d` |
| 貼り付け(カーソルの後ろ/下) | `p` |
| 貼り付け(カーソルの前/上) | `P` |

`y`/`d`した内容は自動的に「無名レジスタ」に入り、**同じNeovimセッション内であれば
別のファイル(バッファ)に切り替えても`p`で貼り付けられる**。`model.py`で`yy`して
`train.py`に移動して`p`、といった使い方が普通にできる。

### 名前付きレジスタ(複数のクリップボードを同時に持つ)

実験コードを組み立てるときなど、「3つの別々のスニペットを同時にキープしておいて、
順番に貼り付けたい」場面で使う。

```
"ayy    " a という名前のレジスタに1行コピー
"byy    " b という名前のレジスタに別の1行コピー
"ap     " a の内容を貼り付け
"bp     " b の内容を貼り付け
```

例: 複数の実験(experiment_v1, v2, v3)それぞれのハイパーパラメータ行を`"a`〜`"c`に
コピーしておいて、比較表を作るときに順番に貼り付ける、といった使い方。

### システムクリップボード(Windows側)へのコピーについて

**この環境ではNeovim内蔵の`"+y`(システムクリップボードレジスタ)は使えない**
(`:checkhealth`で確認済み。clipboardプロバイダ未設定)。VSCodeの`Ctrl+C`感覚で
`"+y`を使おうとしても、Windows側には届かない。

Windows側のアプリ(Slackやブラウザ、Excelなど)にコピーしたいときは、Neovimの
レジスタ機能ではなく**マウス選択**を使う。ただし1点注意:

- Neovimは`mouse=a`(全モードでマウス有効)なので、**素のクリックドラッグは
  Neovim自身のビジュアルモード選択になり、ターミナル(Zellij/WezTerm)側の
  コピー機能は発動しない**
- ターミナル側の選択(Zellijの`copy_on_select`経由でWindowsクリップボードに届く方)を
  使いたい場合は、多くのターミナルと同様に**Shiftを押しながらドラッグ**して
  Neovim側のマウス捕捉を回避する

まとめると: 「Neovim内で完結するコピペ」→ `y`/`d`/`p`で十分。
「Windows側の別アプリに持っていきたい」→ Shift+ドラッグ選択([`zellij.md`](./zellij.md)の
コピー節も参照)。

### 矩形選択(列単位のコピー)

タブ区切りのログや、揃った桁のパラメータ一覧など「列」を扱いたいとき。

```
Ctrl+v   " 矩形(Visual Block)モードに入る
j/k      " 縦方向に選択範囲を広げる
y        " コピー
```

例えば実験ログの2列目(数値だけ)を縦に抜き出してコピーしたいときなどに使える。

## カーソルジャンプ

「今どこにいるか」を保ったまま素早く目的の場所に飛ぶための手段が何段階かある。

### 同じ行の中で飛ぶ

| したいこと | キー |
|---|---|
| 次の`(`や`,`など特定の文字へ | `f(`(fの後に対象の文字) |
| 直前の特定の文字へ | `F(` |
| 特定の文字の手前まで | `t(` / `T(` |
| 対応する括弧へジャンプ | `%`(`(`の上で押すと対応する`)`へ) |

例: `self.optimizer = torch.optim.Adam(model.parameters(), lr=1e-3, weight_decay=1e-5)`
のような長い1行で、`lr=`の値だけ素早く書き換えたいとき、`f=`で`=`の上まで飛んで
`l`で1つ進み`ciw`(後述)で書き換える、といった使い方。

### ファイル内の任意の場所へ飛ぶ(Flash)

`s`(Flash)を押すと、画面内の候補位置にラベル文字が表示され、そのラベルを押すだけで
一気にジャンプできる。長い関数の中で目的の変数の再代入箇所へ飛ぶ、といった用途に
`/`で検索するより速いことが多い。`S`はtreesitterのノード単位(関数・ブロックなど)で
候補を出す版。

### ブックマーク(マーク)

「今の場所を覚えておいて、別の場所を見てから戻ってきたい」ときに使う。ジャンプリスト
(下記)と違い、**明示的に名前を付けて戻れる**のが特徴。

| したいこと | キー |
|---|---|
| 現在位置に`a`という名前でマークを付ける | `ma` |
| マーク`a`の行に戻る | `` 'a `` |
| マーク`a`の正確な位置(行・列)に戻る | `` `a `` |

例: `train.py`の呼び出し元を見ながら`model.py`の実装を確認したいとき、
`train.py`側で`ma`しておき、`model.py`を見終わったら`` `a ``で一発で戻れる
(バッファを行き来する`Ctrl+^`と組み合わせても良い)。

### ジャンプリスト(暗黙の移動履歴)

`gd`(定義ジャンプ)・検索・`G`など「大きな移動」をすると、Vimは自動的に移動履歴を
記録している。マークのように名前を付けなくても、ブラウザの「戻る/進む」感覚で
辿れる。

| したいこと | キー |
|---|---|
| 1つ前のジャンプ地点に戻る | `Ctrl+o` |
| 進む | `Ctrl+i` |

**これが一番出番が多い。** 例えば`gd`でモデルクラスの定義にジャンプしたあと、
元のtrain.pyの呼び出し箇所に戻りたければ`Ctrl+o`を押すだけでよい
(マークを事前に置く必要がない)。

### LSPによるジャンプ(おさらい)

[`lazyvim.md`](./lazyvim.md)のLSP章の内容だが、コードジャンプの主力なのでここでも
まとめておく: `gd`(定義)・`gr`(参照)・`K`(ホバー)。いずれも移動後は上記の
ジャンプリスト(`Ctrl+o`)で戻れる。

## 関数・クラス単位で選択・編集する(テキストオブジェクト)

VSCodeで「関数を選択してコピー」する感覚に近い、Vimの`a`(around)/`i`(inside)
テキストオブジェクトの応用。カーソルがその関数/クラスの**内側であればどこでもよい**
(先頭行にいる必要はない)。

| したいこと | キー |
|---|---|
| 関数を丸ごとコピー | `yaf`(コメント・デコレータ含めず本体のみなら`yif`) |
| 関数を丸ごと削除 | `daf` |
| 関数の中身だけ書き換え | `cif` |
| クラスを丸ごとコピー/削除 | `yac` / `dac` |
| 括弧の中身をコピー/書き換え | `yi(` / `ci(` |
| クォートの中身を書き換え | `ci"`(ハイパーパラメータ名の文字列などに便利) |
| 単語を書き換え | `ciw` |
| 数値だけ書き換え | `cid`(数字部分のみを対象にできる) |

### よくある実例: 実験用に関数を複製して調整する

1. ベースにしたい`train_step`関数の内側にカーソルを置き`yaf`でコピー
2. ファイル末尾へ移動(`G`)、`o`で改行して`p`で貼り付け
3. 関数名を変更(`ciw`で`train_step`→`train_step_v2`など)
4. 中身を`ci(`や`ciw`で必要な箇所だけ書き換え

### 関数・クラス・引数の間を移動する

| したいこと | キー |
|---|---|
| 次の関数の先頭へ | `]f` |
| 前の関数の先頭へ | `[f` |
| 次の関数の終わりへ | `]F` |
| 次のクラスの先頭へ | `]c` |
| 次の引数へ | `]a` |
| 前の引数へ | `[a` |

長いモデル定義ファイル(何十個もの`nn.Module`のメソッドが並ぶような)を上から
ざっと見ていきたいときに`]f`を連打すると、関数単位でスクロールできる。

## 複数ファイルにまたがる編集

研究コードは`model.py`/`train.py`/`dataset.py`/`config.yaml`/`utils.py`のように
分かれているのが普通なので、これが一番実戦で使う場面が多い。

### 2つのファイルを並べて見比べながら編集する

```
:vsplit config.yaml
```

`train.py`を開いた状態で`config.yaml`を縦分割表示。`Ctrl+w` → `h`/`l`で行き来する。
ハイパーパラメータの値をconfigで確認しながらtrain.py側のデフォルト値を直す、
といった作業に。

### バッファ間を素早く行き来する

| したいこと | キー |
|---|---|
| 直前のバッファに戻る | `Ctrl+^` |
| バッファ一覧から選ぶ | `<space>,` |
| 次/前のバッファ | `L` / `H` |

`model.py` ⇔ `train.py`のように2ファイルだけを往復するなら`Ctrl+^`が一番速い。

### 同じ変数名・関数名をプロジェクト全体で探す/直す

| したいこと | キー |
|---|---|
| プロジェクト全体を検索(VSCodeの`Ctrl+Shift+F`) | `<space>sg` |
| 検索結果を1件ずつ確認しながら置換 | `<space>sr` |
| LSPでシンボルを安全にリネーム(その名前を参照している箇所全部) | `grn` |

例: `learning_rate`という変数名を`lr`に統一したいとき、Python変数として一貫して
使われているなら`grn`(LSPリネーム)が安全。文字列の中(config.yamlのキー名など)まで
含めて機械的に置換したいなら`<space>sr`。

### grep結果を複数ファイルにまたがって順番に処理する

1. `<space>sg`で`TODO`や`FIXME`、あるいは`batch_size`のような気になるキーワードを検索
2. 結果がquickfixリストに入るので`]q`/`[q`で1件ずつ、**ファイルをまたいで**移動
3. 各箇所を確認・修正しながら進む

複数の`experiment_*/train.py`にまたがって同じ書き換えをして回るときなどに便利
(1ファイルずつ手動で開き直す必要がない)。

## 数値・繰り返し編集

### 数値をキーひとつで増減する

| したいこと | キー |
|---|---|
| カーソル上/直後の数値を+1 | `Ctrl+a` |
| -1 | `Ctrl+x` |

`batch_size = 32`の`32`にカーソルを合わせて`Ctrl+a`を押すごとに`33`, `34`...と
増えていく。学習率の桁を変えたり、seed値を変えたりする微調整に地味に便利
(ビジュアルモードで複数行選択してから`Ctrl+a`すると、選択した全行の数値をまとめて
+1することもできる)。

### 同じ編集を繰り返す(ドットリピート)

| したいこと | キー |
|---|---|
| 直前の変更をもう一度実行 | `.` |

`ciw`で1つの変数名を書き換えたあと、次の出現箇所にカーソルを移動して`.`を押すだけで
同じ書き換えが繰り返される。`*`(カーソル上の単語を検索)と組み合わせると
「単語を探して→書き換えて→`.`で次も」という強力なリファクタリングの流れになる。

### マクロ(操作列をまるごと記録して繰り返す)

似たような書き換えを何ブロックも(例えば10個のexperiment configブロック)
繰り返し適用したいときに使う。

```
qa          " 'a' という名前でマクロ記録開始
(操作をする: 例えばciwで値を書き換えてEscで抜ける、次の行にjで移動、など)
q           " 記録終了
@a          " 記録した操作を1回再生
9@a         " さらに9回繰り返す(合計10回)
```

VSCodeのマクロ機能より地味に見えるが、「1回分の操作を手でやって見せる → あとは
機械的に繰り返す」という発想なので、複雑な条件分岐が要らない単純作業には非常に強い。

## シチュエーション別実例(研究ワークフロー)

### 「model.pyとtrain.pyを行き来しながら実装したい」

`Ctrl+^`(直前バッファに戻る)を中心に、必要なら`:vsplit`で両方同時に見える状態に
する。LSPの`gd`でクラス定義に飛んだ場合は`Ctrl+o`で元の位置に戻れる。

### 「config.yaml(Hydra/OmegaConf形式)のハイパーパラメータを見ながらtrain.pyを書きたい」

```
:vsplit configs/train_config.yaml
```

taplo(TOMLの場合)やyaml-language-serverの補完を効かせつつ、両方を同時に見ながら
値を合わせ込める。

### 「実験Aのtraining loopをコピーして実験B用に少し変えたスクリプトを作りたい」

`yaf`で`train_step`関数をコピー→新しいファイル(`:e train_step_v2.py`)を開いて
`p`で貼り付け→`ciw`で細部を調整。[`python.md`](./python.md)の`uv run`と組み合わせて
すぐ動作確認できる。

### 「`learning_rate`という変数名をプロジェクト全体で統一したい」

Pythonコードとしての参照なら`grn`(LSPリネーム、対象ファイル内で安全に一括変更)。
config.yamlのキー名やコメント中の記述まで含めて機械的に直したいなら`<space>sr`
(Search and Replace)でプロジェクト全体を横断。

### 「長いモデル定義ファイルの中で目的のメソッドにすぐ飛びたい」

`]f`/`[f`で関数単位に飛び飛びで移動、目的の名前が分かっているなら`/forward`のように
検索、あるいは`<space>ss`(LSP Symbols)でそのファイル内のシンボル一覧から選ぶのが速い。

### 「SMILES文字列や化合物ID、ファイルパスなど特殊な記号を含む文字列を検索したい」

`/`検索は正規表現なので、`(`や`[`などSMILES特有の記号はエスケープが必要な場合がある
(`\(`のように)。確実なのはカーソルを対象の上に置いて`*`(カーソル上の単語を検索)。
記号を含む「単語」全体を対象にしたいときは、まず`viw`などで範囲を目視確認してから
検索するとよい。

### 「複数の`experiment_XX/train.py`を間違えずに編集したい」(同名ファイルが複数ある場合)

バッファ一覧(`<space>,`または`<space>fb`)はフルパスの違いで区別して表示されるので、
どの`experiment_XX`のものか確認しながら選べる。開く前に迷う場合は`<space>fr`
(最近使ったファイル)やファイルツリー(`<space>e`)でディレクトリ構造ごと確認するのが
安全。

### 「バッチサイズや学習率など、複数箇所に散らばった数値パラメータを一括で変える」

同じ変数への代入が複数箇所にあるだけなら`<space>sg`で検索して`]q`/`[q`で1件ずつ
確認しながら`Ctrl+a`/`ciw`で直す。機械的な一括置換でよいなら`<space>sr`。

### 「一時的にコードブロックをコメントアウトして、別のモデル構成を試したい」

ビジュアルモード(`V`)で対象行を選択して`gc`でコメントアウト/解除。
1行だけなら`gcc`。試したい構成をコメントアウトで切り替えながら`uv run`で
動作確認、を繰り返す運用がしやすい。

### 「コードの一部を別の場所(utils.pyなど)に切り出したい」

`dap`(段落ごとカット、関数全体なら`daf`)→ 対象ファイルに`Ctrl+^`または
`<space>ff`で移動 → `p`で貼り付け。切り出し元にimport文を追加するのを忘れずに。

### 「大きなログファイルやCSVの特定行・特定のエポックの結果を見たい」

`:N`(N行目へジャンプ)、`/epoch 50`のような検索、または`G`でファイル末尾
(学習ログなら最新の結果はたいてい末尾)。長い行が折り返されて見づらい場合は
`:set nowrap`で折り返しを止めると、表形式のログが読みやすくなることがある。

### 「Undoで前のモデル構成に戻したい/どこまで戻せるか確認したい」

`u`で1手ずつ戻る、`Ctrl+r`でやり直し。何段階も試行錯誤した後にどこまで遡れるか
視覚的に確認したいときは`<space>su`(Undotree)。

## 困ったときの対処

### 「マウスでドラッグしたのにWindows側にコピーされない」

Neovim自身がマウスを捕捉している(`mouse=a`)ため。Shiftを押しながらドラッグして
ターミナル側の選択に切り替える(上記「システムクリップボード」参照)。

### 「`daf`/`yaf`などのテキストオブジェクトが反応しない」

対象の言語のtreesitterパーサーが導入されているか、ファイルが正しく認識されて
いるか(`:set filetype?`)を確認する。Python/TOML/Dockerfile/Markdown/TeXなど、
このリポジトリの`extras`で有効化されている言語では動作確認済み。

### 「ジャンプしすぎて元の場所が分からなくなった」

慌てず`Ctrl+o`を連打すれば、ジャンプ前の位置まで遡れる。
