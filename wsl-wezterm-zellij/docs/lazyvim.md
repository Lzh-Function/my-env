# LazyVim編: VSCodeの代わりにNeovimで書く

LazyVimは「Neovim(Vimの後継)に、VSCode的な便利機能(ファイル検索・LSP・Git連携など)を
最初から詰め込んだ設定集」。ベースがVimである以上、**モードという考え方**にだけは
慣れる必要があるが、それさえ乗り越えれば残りはVSCodeとそう変わらない。

このページのキーバインドは、この環境に実際にインストールされている設定から
`nvim --headless`で直接取得した実データ(推測ではない)。

## 最初にこれだけ覚える

VSCodeから来た人が最初の1日で覚えるべきなのはこの数個だけ。

| したいこと | キー |
|---|---|
| 今すぐ何もかも忘れて安全な状態に戻る | `Esc`を連打(ノーマルモードに戻る) |
| 入力(タイピング)を始める | `i` |
| 保存 | `Esc` → `:w` → `Enter`(または`<space>fs`) |
| コマンドパレット的に「何ができるか」を知りたい | `<space>`(スペース)を押して**少し待つ** |
| ファイルを名前で開く | `<space><space>` または `<space>ff` |
| ファイル一覧(サイドバー) | `<space>e` |
| 元に戻す/やり直す | `u` / `Ctrl+r` |
| コピー/切り取り/貼り付け | `y`(yank) / `d`(delete) / `p`(paste) |
| 定義にジャンプ | `gd` |
| 終了 | `Esc` → `:q` → `Enter` |

## Vimのモードという考え方(最重要・最初の壁)

VSCodeでは「常にどこでも文字が打てる」。LazyVim(Neovim)は違って、**今どのモードにいるか**で
キーの意味が変わる。

| モード | 何をする場所か | 入り方 | 抜け方 |
|---|---|---|---|
| **ノーマルモード**(既定) | 移動・削除・コピーなど「操作」をする | 起動時はここ | ── |
| **インサートモード** | 実際に文字をタイピングする | `i`/`a`/`o`など | `Esc` |
| **ビジュアルモード** | 範囲を選択する(VSCodeのドラッグ選択に近い) | `v`/`V`/`Ctrl+v` | `Esc` |
| **コマンドモード** | `:w`のようなコマンドを打つ | `:` | `Enter`か`Esc` |

**迷ったらとにかく`Esc`を押してノーマルモードに戻る**、というのがVim全体を通じての鉄則。
「あれ、文字を打っても反映されない」「変な記号が入力される」というときは、ほぼ確実に
ノーマルモードでタイピングしようとしている(=インサートモードに入っていない)。

### ノーマルモードからインサートモードに入る方法いろいろ

VSCodeの「クリックしてすぐ入力」と違い、**どこから・どう入力を始めるか**によってキーを
使い分ける。最初は`i`だけ覚えれば十分。

| キー | 動作 |
|---|---|
| `i` | カーソルの位置から入力開始(Insert) |
| `a` | カーソルの1つ後ろから入力開始(Append) |
| `o` | 下に新しい行を作って入力開始 |
| `O` | 上に新しい行を作って入力開始 |
| `A` | 行末に移動して入力開始 |

## 移動(モーション): マウスより速い理由

VSCodeでもカーソルキーやマウスで移動できるが、Vimは「移動そのものがコマンド」という設計。
最初は慣れないが、覚えると逆にマウスより速く動けるようになる。

| したいこと | キー |
|---|---|
| 上下左右(矢印キーでもOK) | `h`(左) `j`(下) `k`(上) `l`(右) |
| 単語単位で進む/戻る | `w` / `b` |
| 行の先頭/末尾 | `0` / `$` |
| ファイルの先頭/末尾 | `gg` / `G` |
| 半ページ下/上にスクロール | `Ctrl+d` / `Ctrl+u` |
| N行目にジャンプ | `:N`(例: `:42`で42行目) |
| 直前のカーソル位置に戻る | `Ctrl+o`(戻る) / `Ctrl+i`(進む) |
| 対応する括弧に移動 | `%` |

**慣れないうちは矢印キーやマウスクリックで移動してよい。** `hjkl`は後から自然に身につく。

## 編集操作の基本(コピペ・削除・元に戻す)

VSCodeの「選択してコピー」ではなく、「動詞(操作) + 名詞(範囲)」という組み立て方をする。
これがVimの操作体系の本質。

| VSCodeの操作 | Vimでの考え方 | 例 |
|---|---|---|
| 1文字削除(Delete/Backspace) | `x`(カーソル位置を削除) | `x` |
| 行を削除(カット) | `dd` | `dd` |
| 単語を削除 | `d` + `w`(単語まで削除) | `dw` |
| 行をコピー | `yy`(yank=コピー) | `yy` |
| 貼り付け | `p`(カーソルの後ろに) | `p` |
| コピー(選択範囲) | ビジュアルモードで選択 → `y` | `v` → 移動 → `y` |
| 元に戻す(`Ctrl+Z`) | `u` | `u` |
| やり直し(`Ctrl+Shift+Z`) | `Ctrl+r` | `Ctrl+r` |
| 全選択(`Ctrl+A`) | `ggVG` | `gg` → `V` → `G` |

「`d` + 移動コマンド」で削除される範囲が決まる、という組み合わせ方が分かると急に楽になる。
`dw`(単語を消す)、`d$`(行末まで消す)、`dgg`(先頭まで消す)のように、
**動詞(`d`/`y`/`c`) + 移動(`w`/`$`/`gg`など)** で好きな範囲を操作できる。

### 「行をまるごと消したいだけ」など、よく使う組み合わせ

| したいこと | キー |
|---|---|
| 行を削除 | `dd` |
| 行を複製 | `yy` → `p` |
| 単語だけ書き換え(削除して即入力モード) | `cw`(change word) |
| 行末まで書き換え | `c$` |
| インデントを下げる/上げる | `<<` / `>>` |
| 複数行選択して一括インデント | `V`で複数行選択 → `>`(または`<`) |
| コメントアウト/解除(行) | `gcc` |
| コメントアウト/解除(選択範囲) | ビジュアルモードで選択 → `gc` |

## which-key: コマンドパレットの代わり

LazyVimの核となる仕組み。**リーダーキー(`<space>`)を押してそのまま少し待つ**と、
「次に何を押せばどんな操作ができるか」がポップアップで一覧表示される。

```
<space> を押して待つ
  → f (find系)  b (buffer系)  g (git系)  s (search系) ... とグループが表示される
  → 例えば f を押すと
  → ff (Find Files)  fg (git files)  fr (Recent) ... とさらに絞り込まれる
```

**キーバインドを全部暗記する必要はない。** `<space>`を押して待つ → 目当てのグループの
文字を押す → また待つ、を繰り返せば目的の操作にたどり着ける。これがVSCodeの
`Ctrl+Shift+P`(コマンドパレットで名前検索)に一番近い体験。

似たような仕組みで、あるキー操作の**続き**を知りたいときは`<space>?`(Buffer Keymaps)を
押すと、今のバッファで使えるキーバインド一覧が出る。

## バッファとウィンドウ: VSCodeの「エディタタブ」はこっち

`docs/README.md`で触れた通り、**VSCodeの「複数ファイルをタブで開く」に一番近いのは
Neovimの「バッファ」**。Vim独自の`:tabnew`(通称Vimタブ)はこの環境ではほぼ使わない。

| したいこと | キー |
|---|---|
| 開いているファイル一覧を見る | `<space>,`(Buffers) または `<space>fb` |
| 次のバッファへ | `L`(Shift+l) または `]b` |
| 前のバッファへ | `H`(Shift+h) または `[b` |
| バッファを閉じる | `:bd`(コマンド。`<space>,`の一覧を開いて選んで閉じることもできる) |
| 特定のバッファに一発でジャンプ | `<space>bj`(Pick Buffer。画面にラベルが出て選ぶ) |

画面上部にはバッファ一覧がタブのように並んで表示される(bufferline)ので、見た目は
VSCodeのタブバーとほぼ同じに見える。ただし**これはZellijのタブとは別物**なので注意
(`docs/README.md`の「タブが3種類ある」参照)。

### ウィンドウ分割(VSCodeの画面分割)

Neovim自体にも画面分割機能がある(Zellijのペイン分割とは別レイヤー)。

| したいこと | キー |
|---|---|
| 縦に分割 | `:vsplit`(`:vs`) |
| 横に分割 | `:split`(`:sp`) |
| 分割したウィンドウ間を移動 | `Ctrl+w` → `h`/`j`/`k`/`l` |
| 分割したウィンドウを閉じる | `:q` |

普段は「Neovim1枚 + Zellijのshellペイン」で十分なので、Neovim内の分割はコードを2箇所
同時に見比べたいときなど、必要な場面だけ使えばよい。

## ファイル操作・検索

| したいこと(VSCodeの操作) | LazyVimでの操作 |
|---|---|
| ファイルを名前で開く(`Ctrl+P`) | `<space><space>` または `<space>ff` |
| ファイル内を検索(`Ctrl+F`) | `/`(Vim標準の検索)で入力→`Enter`、`n`/`N`で次/前 |
| プロジェクト全体を検索(`Ctrl+Shift+F`) | `<space>sg`(Grep, Root Dir) |
| 開いているバッファだけ検索 | `<space>sB`(Grep Open Buffers) |
| 検索して一括置換 | `<space>sr`(Search and Replace) |
| ファイルツリー(サイドバー) | `<space>e` |
| 最近開いたファイル | `<space>fr` |
| 診断(エラー/警告)の一覧 | `<space>sd`(Diagnostics) |
| Undo履歴をツリーで見る | `<space>su`(Undotree) |

`<space>e`のExplorerはVSCodeのサイドバーとほぼ同じ感覚で、矢印キー(または`j`/`k`)で
移動、`Enter`でファイルを開く/フォルダを展開できる。

## LSP(コード補完・定義ジャンプなど)

この環境ではPython(pyright)とLaTeX(texlab)のLSPが有効(`lazyvim.json`の`extras`)。
**必ずファイルを開いてから**(LSPがそのファイルにアタッチしてから)使えるようになる
キーバインドなので、真っ白なバッファでは効かないことに注意。

| したいこと(VSCodeの操作) | LazyVimでの操作 |
|---|---|
| 定義にジャンプ(`F12`) | `gd` |
| 宣言にジャンプ | `gD` |
| 実装を見る | `gI` |
| 型定義を見る | `gy` |
| 参照を探す(`Shift+F12`) | `gr` |
| ホバーでドキュメントを見る(マウスオーバー相当) | `K` |
| シグネチャヘルプ | `gK`(挿入モード中は`Ctrl+s`) |
| リネーム(`F2`) | `grn` または `<space>cr` |
| コードアクション(電球アイコン相当) | `gra` または `<space>ca` |
| コードのソースアクション | `<space>cA` |
| Codelensを実行/更新 | `<space>cc` / `<space>cC` |
| 現在のLSP状態を見る | `<space>cl`(`:LspInfo`と同じ) |
| 次/前のエラー・警告にジャンプ | `]d` / `[d` |
| 全診断を一覧(Problemsパネル相当) | `<space>sd`(Diagnostics)、または`<space>xx`(Trouble) |

**コードフォーマットに専用キーは無い。** LazyVimはVSCodeの「保存時に自動フォーマット」設定を
有効にした状態がデフォルトなので、`:w`(保存)するだけで自動的に整形される
(`<space>cF`は「Markdown内に埋め込まれたコードブロックだけ」を整形する特殊なキーで、
通常のフォーマットとは別物)。

### LSPが効いていないとき

- `<space>cl`(または`:LspInfo`)で、そのファイルの言語用LSPがアタッチされているか確認
- `<space>cm`で`Mason`(LSP/フォーマッタ/リンタのインストーラ)を開き、対象の言語サーバーが
  インストール済みか確認。無ければここからインストールできる
- コンテナ(`zj py`/`zj tex`)では、コンテナ内にLSPが入っている。ホストの`zj`(plain)では
  ホスト側の`~/.local/share/nvim`にインストールされたものを使う(別物として管理されている)

## Git連携

3系統ある: **lazygit**(コミット・ブランチ・stageなど本格操作、VSCodeのSource Control
パネルに一番近い)、**gitsigns系**(`<space>gh*`、今のファイルの変更行=hunkをその場で
ちょいちょい触る用)、そして素の`git`コマンド(shellペインから直接)。

### lazygit(`<space>gg`): メインで使うならこれ

この環境にはlazygitがプリインストールされている(ホストWSL・Python-Work/LaTeX-Work
コンテナすべて)。LazyVimは`lazygit`がPATH上にあると自動で`<space>gg`を有効化する
仕組みなので、追加設定なしでそのまま使える。

| したいこと(VSCodeの操作) | LazyVimでの操作 |
|---|---|
| Source Control パネルを開く | `<space>gg`(Lazygit, Root Dir) |
| カレントディレクトリ基準で開く | `<space>gG`(Lazygit, cwd) |

`<space>gg`を押すとlazygitのフルスクリーンTUIがフローティングウィンドウで開く。ファイル一覧
から`Space`でステージ/アンステージ、`c`でコミット、`P`でpush、`p`でpull、`b`でブランチ一覧、
`Esc`または`q`で閉じてNeovimに戻る、というのが基本の流れ。VSCodeのSource Controlパネルの
操作感にかなり近く、コミット単位のグラフ表示やインタラクティブなステージングもできるので、
**日常のコミット・ブランチ操作はまずこれを使えばよい**。

### gitsigns系(`<space>gh*`): エディタ上でその場確認・部分ステージ

ファイルを編集しながら「この数行だけステージしたい」「この行、誰がいつ変更した?」を
その場でサッと確認したいときに使う。**Gitリポジトリ内のファイルを開いているときだけ**効く。

| したいこと(VSCodeの操作) | LazyVimでの操作 |
|---|---|
| Source Control パネル(変更点一覧) | `<space>gs`(Git Status) |
| 差分を見る(hunk単位、プロジェクト全体) | `<space>gd`(Git Diff hunks) |
| originとの差分 | `<space>gD` |
| stashを見る | `<space>gS` |
| 次/前の変更行(hunk)にジャンプ | `]h` / `[h` |
| 最初/最後の変更行にジャンプ | `[H` / `]H` |
| その行のBlame(誰がいつ変更したか) | `<space>ghb`(Blame Line) |
| ファイル全体のBlame | `<space>ghB`(Blame Buffer) |
| 変更行だけステージする(`git add`のhunk版) | `<space>ghs`(Stage Hunk) |
| 変更行を元に戻す | `<space>ghr`(Reset Hunk) |
| ファイル全体をステージ/リセット | `<space>ghS` / `<space>ghR` |
| 変更差分をインラインでプレビュー | `<space>ghp`(Preview Hunk Inline) |
| ファイル全体の差分を見る | `<space>ghd`(Diff This) |

### 使い分けの目安

- **「今書いてるファイルの、この数行だけ確認/ステージしたい」** → gitsigns(`<space>gh*`)。
  エディタを離れずその場で完結する
- **「コミットしたい・ブランチを切りたい・履歴を追いたい」** → lazygit(`<space>gg`)。
  VSCodeのSource Controlパネルに近い一覧性で操作できる
- **細かいオプション付きの操作**(`git rebase -i`など) → 隣のshellペインで素直に`git`
  コマンドを打つのが確実

## 設定変更・拡張機能管理

| したいこと(VSCodeの操作) | LazyVimでの操作 |
|---|---|
| settings.jsonを編集 | `~/.config/nvim/lua/config/options.lua`を編集 |
| キーバインドを追加 | `~/.config/nvim/lua/config/keymaps.lua`を編集 |
| 拡張機能(プラグイン)管理 | `:Lazy`(インストール状況・更新・ログ) |
| 拡張機能を追加する | `~/.config/nvim/lua/plugins/`配下に`.lua`ファイルを作る |
| 言語サポートの追加(Python/TeX以外) | `~/.config/nvim/lazyvim.json`の`extras`に追記、または`:LazyExtras` |
| LSP/フォーマッタ/リンタの管理 | `:Mason` |

`~/.config/nvim`はホストとコンテナで共有(bind mount)されているので、**どちらで編集しても
両方に反映される**(このリポジトリ独自の仕組み。`../README.md`参照)。

## 困ったときの対処

### 「訳が分からなくなった」

とにかく`Esc`を連打してノーマルモードに戻る。それでも復帰しないなら`:q!`で保存せず終了して
開き直す(未保存の変更は失われるので注意)。

### 「保存しないでうっかり閉じてしまった」

Undo履歴自体はファイルを開き直すと失われるが、LazyVimは自動でスワップファイル/バックアップを
持つことがある。`<space>su`(Undotree)は開いている間の変更履歴を視覚的に遡れるので、
編集中に「あの状態に戻したい」と思ったらまずここを確認する。

### 「差分(diff)を見比べながら編集したい」(VSCodeのマージエディタ相当)

`:vsplit`で画面を縦分割し、片方で元のファイル・もう片方で編集中のファイルを開くか、
`<space>gd`のGit diffビューを使う。

### 「複数箇所を同時に編集したい」(VSCodeのマルチカーソル相当)

Vimに「マルチカーソル」という概念はそのままは無いが、代わりに:

- **同じ変更を複数行に繰り返す**: 1行目で操作した内容を`.`(ドットリピート)で次の行にも
  繰り返す、または`Ctrl+v`(矩形選択)で複数行を選んでから`I`/`A`で一括挿入
- **同じ単語を連続で置換**: `*`で現在の単語を検索してハイライト→`cgn`で1つ書き換えて
  `.`を押すたびに次の一致箇所も同様に書き換わる
- **プロジェクト全体の一括置換**: `<space>sr`(Search and Replace)

最初はVSCodeのマルチカーソルほど直感的ではないが、慣れると`:%s/古い/新しい/g`
(全体置換コマンド)も含めて強力な武器になる。
