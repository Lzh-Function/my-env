# Explorer編: ファイルツリーで移動する(`<space>e`)

[`lazyvim.md`](./lazyvim.md)の「ファイル操作・検索」で軽く触れた`<space>e`(Explorer)を、
「ディレクトリ移動」に絞って深掘りする。**VSCodeのサイドバーと一番挙動が違う部分**なので、
独立したページにしている。

このページのキーバインドと挙動は、実際にこの環境のNeovimを操作して検証済み
(バッファのキーマップを直接ダンプして確認、`explorer_up`/`explorer_focus`などの
実装コードも直接確認した上で記載している。推測ではない)。

## 最初にこれだけ覚える

| したいこと | キー |
|---|---|
| Explorerを開く(プロジェクトルート基準) | `<space>e` |
| Explorerを開く(今のカレントディレクトリ基準) | `<space>E` |
| ファイルを開く/ディレクトリを展開・折りたたみ | `Enter` または `l` |
| ディレクトリを閉じる | `h` |
| **親ディレクトリへ移動("..")** | `Backspace` |
| **今見ているディレクトリを新しい起点にする(ジャンプ)** | `.` |
| ジャンプ**かつ**Neovim自体のカレントディレクトリも変える | `Ctrl+c` |
| **パスを直接指定してジャンプ** | `:e <パス>` |
| 隠しファイル(`.`始まり)の表示切り替え | `H` |
| `.gitignore`対象ファイルの表示切り替え | `I` |
| 今いる場所(フルパス)を確認 | `Ctrl+g` |
| 閉じる | `q` または `Esc` |

## 大前提: Explorerは「サイドバー」ではなく「ピッカー」

VSCodeのExplorerサイドバーは**常に画面の隅に居座り続ける**独立したパネル。対して
`<space>e`のExplorerは実体としては`<space>ff`(Find Files)と同じ「ピッカー」機構を
流用したもので、**ファイルを1つ選ぶと(ディレクトリではなくファイルを`Enter`/`l`した
時点で)そのファイルが開いて、Explorer自体は閉じる**。VSCodeのように「サイドバーは
開けっぱなしでエディタ側だけ切り替える」という常駐イメージとは違うので注意
(`docs/README.md`の用語対応表にある通り、この環境で「常駐サイドバー」に一番近いのは
実は**バッファ一覧**(`<space>,`)の方)。

必要になったらまた`<space>e`で呼び出せばよいだけなので、実害はほぼないが、
「閉じたはずのExplorerがどこかに残っている」ということは起きない、と覚えておくと
混乱しない。

## 開き方: `<space>e`と`<space>E`の違い

| キー | 開始地点 |
|---|---|
| `<space>e`(`<space>fe`) | **プロジェクトルート**(自動検出) |
| `<space>E`(`<space>fE`) | **Neovim の現在のカレントディレクトリ**(`:pwd`) |

「プロジェクトルート」の自動検出順は: ①今開いているファイルのLSPルート → ②一番近い
祖先ディレクトリの`.git` → ③どちらも無ければNeovim起動時のカレントディレクトリ、
という優先順位。`zj py`/`zj tex`のコンテナ環境では`/workspace`(または相当のマウント先)
が事実上固定のプロジェクトルートになるので、`<space>e`は基本いつも同じ場所から
始まると考えてよい。

**`:cd`や後述の`Ctrl+c`で作業ディレクトリを変えた後**は、`<space>e`(プロジェクトルート
基準)ではなく`<space>E`(現在地基準)を使うと、その変更後の場所からExplorerが開く。
「さっき移動したはずなのに元の場所からExplorerが開く」と感じたら、`<space>e`と
`<space>E`を間違えていないか確認する。

## ツリーの中を移動する(展開・折りたたみ)

| したいこと | キー |
|---|---|
| カーソルを上下に動かす | `j` / `k`(矢印キーでも可) |
| ディレクトリを展開する/ファイルを開く | `l` または `Enter` |
| ディレクトリを折りたたむ | `h` |
| リストの先頭/末尾へ | `gg` / `G` |

VSCodeのサイドバーと同じく、ディレクトリは階層をインデントで表現したツリー表示で、
`l`/`Enter`で展開・ファイルは即オープン、`h`で折りたたむ。ここまではVSCode感覚のまま
で問題ない。

## ディレクトリを移動する(本題)

ここが一番の要点。「ツリーの中で展開する」(上記)と「Explorer自体の起点(ルート)を
別の場所に移す」(このセクション)は別の操作、という点を区別すると理解しやすい。

### 親ディレクトリへ("..")

```
Backspace
```

今のExplorerの起点の**1つ上**のディレクトリを新しい起点にする(実装的には
「今の起点の`dirname`を取る」だけの単純な処理で、**プロジェクトルートで
下げ止まったりしない**)。つまり`<space>e`でプロジェクトルートを開いたあとでも、
`Backspace`を連打すれば`~/workspace`、`~`、さらに上……とどこまでも遡れる。
VSCodeのExplorerには無い操作(VSCodeはワークスペースの外に出られない)なので、
これがこの環境で一番便利な点の1つ。

### 別のディレクトリへジャンプする(3つの方法)

**方法1: ツリーの中で目的のディレクトリにカーソルを合わせて`.`**

```
.  (ピリオド)
```

カーソルが乗っているディレクトリを新しい起点にして、Explorerをそこから開き直す
(`explorer_focus`という操作)。「今開いているディレクトリの中の、あるサブフォルダの
中身**だけ**を見たい」ときに、いちいち`l`で階層を降りていかなくても一発でそこが
起点になる。深い階層に潜ったあとで全体を見返したいときは、前述の`Backspace`で
戻ればよい。

**方法2: `Ctrl+c`(Neovim自体のカレントディレクトリごと移動)**

```
Ctrl+c
```

`.`と似ているが、こちらはExplorerの表示だけでなく**Neovim自体の作業ディレクトリ
(`:tcd`相当)もそのディレクトリに変更する**。これ以降`<space>ff`(Find Files)や
`<space>sg`(Grep)もそのディレクトリ基準で動くようになる。「これから当分この
サブディレクトリの中だけで作業する」という場面では`.`より`Ctrl+c`の方が
実用的なことが多い。

**方法3: パスを直接指定して開く(`:e <パス>`)**

```
:e ~/workspace/LaTeX-Work
:e ../config
:e /etc
```

Neovimの`:e`(`:edit`)コマンドにディレクトリのパスを渡すと、そのままExplorerが
そこを起点に開く(この環境ではnetrw互換の仕組みとしてSnacksのExplorerが乗っ取って
いるため、`:e <ディレクトリ>`は常にExplorerを開く動作になる。実機で動作確認済み)。
ツリーをたどる手間なく、目的地が分かっているときに一番速い方法。相対パス・絶対パス・
`~`展開いずれも使える。

### 今どこにいるか確認する

```
Ctrl+g
```

Explorerの起点の絶対パスをNeovimの通知として表示する。`Backspace`や`.`を何度か
繰り返したあとで「今どこにいるんだっけ」となったら押す。

## ファイル操作

| したいこと(VSCodeの操作) | キー |
|---|---|
| 新規ファイル/ディレクトリを作成 | `a`(末尾に`/`を付けるとディレクトリ) |
| 名前変更(F2相当) | `r` |
| 移動 | `m` |
| コピー | `c` |
| 削除(ゴミ箱/trashへ) | `d` |
| システムの標準アプリで開く | `o` |
| 一覧を最新の状態に更新 | `u` |
| 複数選択(まとめて操作) | `Tab` |

`d`(削除)は即ゴミ箱行きで、`rm -rf`のような即時完全削除ではない
(誤操作からの復旧余地がある)。複数ファイルをまとめて移動/削除したい場合は
`Tab`で複数選択してから`m`/`d`を押す。

## コピー&ペースト(パスのヤンク)

| したいこと | キー |
|---|---|
| 選択中のファイル/ディレクトリのパスをコピー | `y` |
| コピーしたものを今の場所に貼り付け(実体をコピー) | `p` |

`y`でコピーした内容はレジスタに入るので、**Explorerを一度閉じて別の場所を開き直しても、
同じNeovimセッション内であれば`p`で貼り付けられる**。「`model.py`があるディレクトリを
コピーして、`experiments/`配下に複製を作る」といった操作が、Explorerを閉じずに
`Backspace`/`.`でディレクトリを移動しながら完結できる。

## 検索・Git・診断との連携

| したいこと | キー |
|---|---|
| 今見ているディレクトリ配下をGrep検索 | `<space>/` |
| 今見ているディレクトリでターミナルを開く | `Ctrl+t` |
| プレビューpaneの表示切り替え | `P` |
| 次/前のGit変更ファイルへ | `]g` / `[g` |
| 次/前の診断(エラー/警告)があるファイルへ | `]d` / `[d` |
| 次/前のエラーのみへ | `]e` / `[e` |
| 次/前の警告のみへ | `]w` / `[w` |

ファイル名の左にGitの変更マーク(追加/変更など)やLSP診断のアイコンが出るので、
「どのファイルが変更済みか」「どのファイルにエラーが残っているか」はツリーを
眺めるだけでも分かる。`]g`/`[g`・`]d`/`[d`はそれを使ってジャンプする版。

## シチュエーション別実例

### 「`zj py`のコンテナで、プロジェクトルート以外にある設定ファイルを見たい」

`<space>e`はコンテナにマウントされたプロジェクトルート(`/workspace`相当)から開くので、
それより上の階層(コンテナ内の`/root`や`/etc`など)を見たい場合は`Backspace`で
遡るか、`:e /etc`のようにパス指定で直接開く。

### 「`Python-Work`のExplorerを開いたまま、ふと`LaTeX-Work`側のファイル構成も見たい」

同じホスト上の別ディレクトリでも、パスさえ分かれば`:e ~/workspace/LaTeX-Work`で
一発。ただし`zj py`と`zj tex`はそれぞれ別のコンテナ(別のZellijセッション)なので、
**片方のコンテナから直接もう片方のコンテナのファイルシステムは見えない**
(ホスト側`zj`(plain)からであればどちらの`~/workspace/*`も見える)。

### 「`~/.config/nvim`の設定ファイルを、今の作業を中断せずにちょっと覗きたい」

`:e ~/.config/nvim/lua/plugins`のようにパス指定で開いて確認し、用が済んだら
`Backspace`や`.`で元のプロジェクトのディレクトリに戻る、あるいは`<space>e`
(プロジェクトルート基準)を押し直せば元の場所からやり直せる。

### 「深い階層(`src/models/experiments/v3/`など)に潜ったあと、プロジェクト全体の構成を見返したい」

`Backspace`を必要な回数だけ押すか、`<space>e`を押し直せばプロジェクトルートから
やり直せる(押し直しても今開いているファイルが閉じるわけではない)。

### 「複数の`experiment_XX/`ディレクトリを行き来しながらファイルを探したい」

`.`で`experiment_01/`を起点にして中身を確認 → `Backspace`で親に戻る →
`experiment_02/`にカーソルを合わせて`.`、という繰り返しが、`cd`し直す感覚に近い。
「今後しばらくその実験ディレクトリだけで作業する」と決まっているなら`.`ではなく
`Ctrl+c`で、`<space>ff`/`<space>sg`も含めてそのディレクトリ基準に切り替えてしまう
方が効率的。

## 困ったときの対処

### 「ファイルを選んだらExplorerが閉じてしまった」

想定通りの挙動("大前提"の節を参照)。VSCodeのサイドバーのように常駐しないので、
必要になったらまた`<space>e`/`<space>E`で開き直せばよい。

### 「`Backspace`で行き過ぎて訳が分からない場所に来てしまった」

`Ctrl+g`で今いる場所のフルパスを確認するか、`<space>e`を押し直せばプロジェクト
ルートから仕切り直せる。

### 「`:e <パス>`と打ったのにファイルが開いてしまう(Explorerが開かない)」

指定したパスが**ディレクトリではなくファイル**だった場合はそのまま通常通り
ファイルが開く(正しい挙動)。ディレクトリを指定しているか、末尾のタイプミスが
無いか確認する。

### 「削除したファイルを元に戻したい」

`d`はゴミ箱(trash)への移動なので、OS側のゴミ箱/trashディレクトリ
(`~/.local/share/Trash`など)から手動で救出できる可能性がある。
Explorer自体には「削除の取り消し」操作はない。
