# Markdown編: READMEやメモを書く

このリポジトリ自体のドキュメント(`README.md`や`docs/`配下)もMarkdownで書かれている。
VSCodeの標準Markdownサポート(プレビュー・目次・リンク切れチェックなど)と比べて、
この環境で何が使えて何が使えないかを整理する。

## この環境で実際に動いているもの(検証済み)

`lazyvim.json`の`extras`に`lang.markdown`が追加されており、以下が最初から有効:

- **LSP**: `marksman`。見出しやリンクの補完、リンク切れの検出、ファイル間リンクの
  定義ジャンプ(`gd`)などが使える
- **リッチ表示**: `render-markdown.nvim`。編集中の画面そのものに見出し・箇条書き・
  コードブロックなどが装飾されて表示される(別ウィンドウでのプレビューではなく、
  編集画面自体がそれらしく見えるタイプ)
- **Lint**: `markdownlint-cli2`。見出しレベルの飛び、行末の余分な空白などのスタイル
  違反が診断(`<space>sd`)に出る

**ブラウザでのライブプレビュー**(`markdown-preview.nvim`)は入っているが、自動では
起動しない。使いたい場合は明示的にコマンドを叩く(後述)。

`marksman`が効くということは、`gd`でMarkdown内の`[リンク](./other.md)`から実際に
`other.md`にジャンプできる、複数ファイルにまたがるドキュメント作業(このリポジトリの
`docs/`配下のような構成)でかなり便利、ということでもある。

## シチュエーション別実例

### 「READMEやメモをさっと書きたい」

`zj`(コンテナ不要、plainレイアウト)で十分。`<space>ff`でファイルを開き、
普通にMarkdownを書いて`:w`で保存するだけ。特別な操作は要らない。

### 「見出しの階層や書式を素早く入力したい」

Markdownは基本的に「ただのテキスト」なので、[`lazyvim.md`](./lazyvim.md)の編集操作
(`dd`/`yy`/`gcc`など。ただし`gcc`のコメントアウトはコード用なのでMarkdown中では
あまり使わない)がそのまま活きる。覚えておくと便利なのは:

| したいこと | 操作 |
|---|---|
| 行頭に`#`を追加して見出しにする | `I# `(行頭に`# `を挿入) |
| 箇条書きの行を複製 | `yy` → `p` |
| 表(テーブル)の列を綺麗に揃える | 手打ちでも良いが、崩れたら`gq`で選択範囲を再整形 |
| 太字/斜体で囲む(範囲選択後) | 選択(`v`)してから`**`や`_`を手打ちで前後に挿入 |

VSCodeの「Markdown All in One」拡張のような、ショートカット一発で太字化、といった
専用機能は無い。素のテキスト編集操作の組み合わせで対応する。

### 「見出しにリンクを張って、実際に飛べるか確認したい」

marksmanのおかげで`gd`(定義ジャンプ)がリンクの上で使える。

1. `[こちら](./zellij.md)`のようなリンクを書く
2. カーソルをリンクの上に置いて`gd`
3. `zellij.md`が開けば正しいリンク。開けない/エラーになるならパスが間違っている

このリポジトリの`docs/`配下は実際にこの方法で相互リンクを検証しながら書かれている。

### 「見出しレベルの飛びなど、書き方のクセを指摘してほしい」(VSCodeのMarkdownLint相当)

`markdownlint-cli2`が自動で診断してくれる。`<space>sd`(Diagnostics)で一覧、
または該当行にカーソルを置いて`<space>cl`(LSP情報。厳密にはlintの結果だが同じ
diagnosticsの仕組みに乗る)を確認する。よくある指摘: 見出しレベルを1つ飛ばしている
(`#`の次が`###`など)、行末の余分な空白、連続する空行など。

### 「目次(TOC)を作りたい」

自動生成の仕組みは組み込まれていないので、手で見出し一覧を書くか、他のツール
(`npx markdown-toc`など、コンテナ/ホストにNode.jsは入っているので実行は可能)を
shellペインから使う。

### 「プレビューを見ながら書きたい」(VSCodeの`Ctrl+Shift+V`相当)

編集画面自体はrender-markdown.nvimのおかげである程度「それらしく」表示されるが、
本物のブラウザプレビューが欲しい場合:

```
:MarkdownPreview
```

`markdown-preview.nvim`がブラウザでプレビューを開こうとする。**ただしブラウザは
Windows側にあるため**、`zj`(ホスト)からなら`explorer.exe`同様のWSL interopで
開ける可能性が高いが、`zj py`/`zj tex`(コンテナ内)からは開けない
(このリポジトリで繰り返し出てくる「コンテナからWindows側のGUIは呼べない」制約と同じ)。
うまく開かない場合は、表示されるURL(`http://localhost:xxxx`のようなもの)を
Windows側のブラウザに手動でコピペする。

GitHubで管理しているMarkdownなら、pushしてGitHub上のプレビューで最終確認するのも
実用的な手。

### 「表(テーブル)がずれて見づらい」

Markdownの表はプレーンテキストなので、手で`|`の位置を揃えないと崩れて見える。
几帳面に整形したい場合は、shellペインで`npx prettier --write ファイル.md`
(Node.jsは導入済みなので実行可能)を使うと自動整形できる。

## 困ったときの対処

### 「marksmanが効いていない/リッチ表示にならない」

`<space>cl`(`:LspInfo`)で確認。`.md`拡張子のファイルを開いているか、
ファイル名が正しいかを確認する(拡張子が無いと言語判定されずLSPが立ち上がらない)。

### 「新しいマシンでMarkdownの装飾やlintが効かない」

`~/.config/nvim/lazyvim.json`の`extras`に`lazyvim.plugins.extras.lang.markdown`が
含まれているか確認。含まれていれば`chezmoi apply`後に自動でプラグインが揃うはずだが、
初回だけ`nvim --headless "+Lazy! sync" +qa`(または`:Lazy sync`)を手動で走らせる
必要がある場合がある。
